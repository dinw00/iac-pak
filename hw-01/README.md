# Стенд для показа продукта (ДЗ 1, «Инфраструктура как код»)

Стенд поднимается одной командой перед показом и сносится одной командой после него. Между показами в облаке не остаётся ничего, за что берут деньги.

Он переживает отказ одной машины: страницу отдают несколько веб-серверов в двух зонах доступности, а сетевой балансировщик перестаёт слать запросы на машину, которая не прошла проверку состояния.

## Что входит в стенд

| Ресурс | Имя | Где | Зачем |
|---|---|---|---|
| Сеть | `pak-05-net` | — | своя сеть, не `default` |
| Подсеть A | `pak-05-subnet-a` | `ru-central1-b`, `10.15.1.0/24` | web-1 (и другие нечётные веб-серверы), app-1 |
| Подсеть B | `pak-05-subnet-b` | `ru-central1-d`, `10.15.2.0/24` | web-2 (и другие чётные веб-серверы) |
| NAT-шлюз | `pak-05-nat` | ресурс сети | выход в интернет для машины без публичного адреса |
| Таблица маршрутизации | `pak-05-rt` | привязана к `pak-05-subnet-a` | `0.0.0.0/0 → pak-05-nat` |
| Веб-серверы | `pak-05-web-1`, `pak-05-web-2` | по одному в каждой зоне | nginx на порту `8015`, есть публичный адрес |
| Сервер приложения | `pak-05-app-1` | зона A | nginx на порту `8015`, **без публичного адреса** |
| Целевая группа | `pak-05-tg` | `ru-central1` | веб-серверы |
| Балансировщик | `pak-05-nlb` | `ru-central1` | слушает `80`, отправляет на `8015`, проверка HTTP `:8015/` |

Машины настраиваются при первой загрузке через cloud-init (`cloud-init.yaml.tpl`): ставится nginx, отдаётся страница со словом `vmlab` и именем машины.

## Что нужно

- bash, `yc` (профиль с заданными `folder-id` и `compute-default-zone`), `jq`, `curl`, `ssh`;
- SSH-ключ `~/.ssh/id_ed25519` (создаётся командой `ssh-keygen -t ed25519`) или свой ключ через `--ssh-key`;
- квоты каталога: 3 ВМ, 1 сетевой балансировщик, 1 NAT-шлюз.

## Как пользоваться

```bash
cd hw-01
./create.sh        # поднять стенд (ждёт, пока check.sh не вернёт 0; обычно 4–7 минут)
./check.sh         # проверить: код возврата 0 — всё в порядке, 1 — что-то не так
./destroy.sh       # снести всё с префиксом pak-05-
```

Если файлы потеряли бит исполнения, их можно запускать через `bash create.sh` и т. д.

`create.sh` можно запускать повторно: созданное он пропускает и ничего не дублирует. Если предыдущий запуск прервался, повторный запуск досоздаст недостающее.

## Параметры

Все три скрипта принимают одни и те же параметры. Приоритет такой: **аргумент > переменная окружения > умолчание варианта**.

| Аргумент | Переменная окружения | Умолчание (вариант 05) |
|---|---|---|
| `--prefix` | `PREFIX` | `pak-05` |
| `--zone-a` | `ZONE_A` | `ru-central1-b` |
| `--zone-b` | `ZONE_B` | `ru-central1-d` |
| `--subnet-a` | `SUBNET_A_CIDR` | `10.15.1.0/24` |
| `--subnet-b` | `SUBNET_B_CIDR` | `10.15.2.0/24` |
| `--port` | `PORT` | `8015` |
| `--word` | `WORD` | `vmlab` |
| `--web-count` | `WEB_COUNT` | `2` (меньше 2 нельзя) |
| `--env` | `ENV_NAME` | `lab` |
| `--ssh-user` | `SSH_USER` | `yc-user` |
| `--ssh-key` | `SSH_KEY` | `~/.ssh/id_ed25519.pub` |
| `--no-wait` | `NO_WAIT=1` | create.sh не ждёт готовности |
| `--by-label` | `BY_LABEL=1` | destroy.sh ищет ресурсы по метке `owner=<префикс>` |

Размер машин задаётся только через окружение: `VM_CORES=2`, `VM_MEMORY=1`, `VM_CORE_FRACTION=20`, `VM_DISK_SIZE=20`, `IMAGE_FAMILY=ubuntu-2404-lts`. `VM_PREEMPTIBLE=1` создаёт прерываемые машины: они вдвое дешевле, но облако может остановить их посреди показа, поэтому по умолчанию этот режим выключен.

Примеры:

```bash
./create.sh --web-count 3                  # три веб-сервера
PORT=8080 ./create.sh --port 8015          # победит аргумент: порт 8015
./create.sh --prefix demo --env stage      # второй стенд рядом, с другим префиксом
./destroy.sh --prefix demo
```

Все ресурсы помечаются метками `env=<окружение>,owner=<префикс>`, а машины ещё и меткой `role=web|app`.

## Что проверяет check.sh

```text
✓ балансировщик отвечает: 200 (http://<адрес>/)
✓ ответили машины: pak-05-web-1, pak-05-web-2
✓ сервер приложения 10.15.1.x:8015 отвечает с pak-05-web-1: 200
✓ у pak-05-app-1 нет публичного адреса
```

1. Балансировщик отвечает на `http://<адрес>/` кодом 200.
2. Из 20 запросов через балансировщик ответы пришли больше чем с одной машины.
3. С `pak-05-web-1` (через SSH) сервер приложения отвечает на `http://<внутренний адрес>:8015/` кодом 200.
4. У `pak-05-app-1` нет публичного адреса.

Код возврата 0, если прошли все проверки, и 1, если не прошла хотя бы одна.

## Если check.sh вернул ошибку

| Строка с ✗ | Что проверить |
|---|---|
| балансировщик не найден | стенд не поднят или снесён: `./create.sh` |
| отвечает кодом `000` / не 200 | сразу после создания машины ещё ставят nginx, подождите 2–3 минуты. Состояние целей: `yc load-balancer network-load-balancer target-states pak-05-nlb --target-group-id $(yc load-balancer target-group get pak-05-tg --format json \| jq -r .id)` |
| отвечает только одна машина | вторая машина в статусе `UNHEALTHY`. Зайдите на неё: `ssh yc-user@<публичный IP>`, затем `systemctl status nginx` и `curl localhost:8015`. После `sudo systemctl start nginx` машина вернётся в балансировку за 10–30 секунд |
| сервер приложения недоступен | на `pak-05-app-1` не применился cloud-init, потому что не было выхода в интернет. Проверьте, что у `pak-05-subnet-a` задана таблица `pak-05-rt` (`yc vpc subnet get pak-05-subnet-a`). Затем пересоздайте машину: `yc compute instance delete pak-05-app-1 && ./create.sh` |
| нет публичного адреса у app — ✗ | машину создали с публичным адресом вручную. Удалите её и запустите `./create.sh` |
| `Permission denied (publickey)` | ключ не тот: передайте `--ssh-key` с тем же ключом, с которым создавался стенд |

Если сбой надо разобрать на самой машине без публичного адреса, зайдите через веб-сервер: `ssh -J yc-user@<IP web-1> yc-user@<внутренний IP app-1>`, затем `sudo cloud-init status --long`.

## Уборка

`destroy.sh` удаляет ресурсы в обратном порядке: балансировщик → целевая группа → машины → диски → подсети (перед удалением от подсети отвязывается таблица маршрутизации) → таблица маршрутизации → NAT-шлюз → сеть. В конце он сам проверяет, что ресурсов с префиксом не осталось, и возвращает 0. Ручная проверка:

```bash
yc compute instance list; yc compute disk list; yc vpc address list
yc vpc network list; yc vpc subnet list; yc vpc gateway list; yc vpc route-table list
yc load-balancer network-load-balancer list; yc load-balancer target-group list
```

## Файлы

| Файл | Что делает |
|---|---|
| `create.sh` | поднимает стенд, повторный запуск безопасен |
| `check.sh` | проверяет стенд, возвращает 0 или 1 |
| `destroy.sh` | удаляет всё с префиксом (или меткой) |
| `params.sh` | общие параметры и разбор аргументов, подключается из всех трёх скриптов |
| `cloud-init.yaml.tpl` | шаблон настройки машин |
| `расхождения.md` | что скрипт не умеет (к сравнению с Terraform) |
