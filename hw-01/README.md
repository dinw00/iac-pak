# Стенд для показа продукта (ДЗ 1, «Инфраструктура как код»)

Стенд поднимается одной командой перед показом и сносится одной командой после него. Между показами в облаке не остаётся ничего платного. Он переживает отказ одной машины: страницу отдают два веб-сервера в разных зонах доступности, а балансировщик перестаёт слать запросы на машину, которая не прошла проверку состояния.

## Состав

| Ресурс | Имя | Где | Зачем |
|---|---|---|---|
| Сеть | `pak-05-net` | — | своя сеть, не `default` |
| Подсеть A | `pak-05-subnet-a` | `ru-central1-b`, `10.15.1.0/24` | web-1 (и другие нечётные), app-1 |
| Подсеть B | `pak-05-subnet-b` | `ru-central1-d`, `10.15.2.0/24` | web-2 (и другие чётные) |
| NAT-шлюз | `pak-05-nat` | ресурс сети | выход в интернет для машины без публичного адреса |
| Таблица маршрутизации | `pak-05-rt` | привязана к `pak-05-subnet-a` | `0.0.0.0/0 → pak-05-nat` |
| Веб-серверы | `pak-05-web-1`, `pak-05-web-2` | по одному в каждой зоне | nginx на `8015`, публичный адрес |
| Сервер приложения | `pak-05-app-1` | зона A | nginx на `8015`, **без публичного адреса** |
| Целевая группа | `pak-05-tg` | `ru-central1` | веб-серверы |
| Балансировщик | `pak-05-lb` | `ru-central1` | слушает `80`, раздаёт на `8015`, проверка HTTP `:8015/` |

Машины: Intel Ice Lake, 2 vCPU с долей 20 %, 2 ГБ, прерываемые, загрузочный диск 20 ГБ HDD, `ubuntu-2404-lts`. Настраиваются при первой загрузке через cloud-init (`cloud-init.tpl.yaml`): пользователь `student`, nginx на порту 8015, страница `vmlab on <имя машины>`.

## Что нужно

- WSL с bash, `yc` (профиль с `folder-id`), `jq`, `curl`, `ssh`, `envsubst` (`sudo apt install -y gettext-base`);
- ключ `~/.ssh/id_ed25519.pub`, он попадёт на машины через cloud-init;
- квоты: 3 ВМ, 1 сетевой балансировщик, 1 NAT-шлюз.

## Как поднять, проверить, снести

```bash
cd ~/iac-pak/hw-01
bash create.sh     # поднять; в конце ждёт, пока check.sh не вернёт 0 (обычно 4–7 минут)
bash check.sh      # проверить: код возврата 0 — всё в порядке, 1 — нет
bash destroy.sh    # снести всё с префиксом pak-05-
```

`create.sh` можно запускать повторно: созданное он пропускает и ничего не дублирует. Если запуск прервался посередине, повторный запуск досоздаст недостающее.

## Параметры create.sh

Приоритет: **аргумент > переменная окружения > умолчание варианта 05**.

| Аргумент | Переменная | Умолчание |
|---|---|---|
| `--prefix` | `PREFIX` | `pak-05` |
| `--zone-a` / `--zone-b` | `ZONE_A` / `ZONE_B` | `ru-central1-b` / `ru-central1-d` |
| `--cidr-a` / `--cidr-b` | `CIDR_A` / `CIDR_B` | `10.15.1.0/24` / `10.15.2.0/24` |
| `--port` | `APP_PORT` | `8015` |
| `--greeting` | `GREETING` | `vmlab` |
| `--web-count` | `WEB_COUNT` | `2` (меньше нельзя) |
| `--env` | `ENV_NAME` | `lab` |
| `--boot-size` | `BOOT_SIZE` | `20` |
| `--no-wait` | — | не ждать готовности |

`check.sh` принимает `--prefix`, `--port`, `--greeting`. `destroy.sh` принимает `--prefix` и `--by-label`: с ним ресурсы ищутся по метке `owner=<префикс>`, а не по имени.

```bash
bash create.sh --web-count 3                 # три веб-сервера
APP_PORT=9999 bash create.sh --port 8015     # победит аргумент: 8015
bash create.sh --prefix demo --env stage     # второй стенд рядом
bash destroy.sh --prefix demo
```

Все ресурсы получают метки `env=<окружение>,owner=<префикс>`, машины ещё и `role=web|app`.

## Что проверяет check.sh

```text
✓ балансировщик отвечает: 200 (http://<адрес>)
✓ ответили машины: pak-05-web-1, pak-05-web-2
✓ сервер приложения 10.15.1.x:8015 отвечает с pak-05-web-1: vmlab on pak-05-app-1
✓ у pak-05-app-1 нет публичного адреса
```

## Если check.sh вернул ошибку

| Строка с ✗ | Что делать |
|---|---|
| балансировщик не найден | стенд не поднят или снесён: `bash create.sh` |
| отвечает не 200 / `000` | машины ещё ставят nginx, подождите 2–3 минуты. Состояние целей: `yc load-balancer network-load-balancer target-states --name pak-05-lb --target-group-id $(yc load-balancer target-group get --name pak-05-tg --format json \| jq -r .id)` |
| отвечает только одна машина | вторая `UNHEALTHY`: `ssh student@<её IP> 'sudo cloud-init status --long; sudo nginx -t; systemctl is-active nginx'`. Прерываемую машину облако могло остановить: `yc compute instance list`, затем `yc compute instance start <имя>` |
| сервер приложения недоступен | у `pak-05-subnet-a` нет таблицы маршрутизации, и cloud-init не скачал nginx: `yc vpc subnet get --name pak-05-subnet-a`. Пересоздать машину: `yc compute instance delete pak-05-app-1 && bash create.sh` |
| `Permission denied (publickey)` | стенд создан с другим ключом: `bash destroy.sh && bash create.sh` |

Зайти на закрытую машину можно через веб-сервер: `ssh -J student@<IP web-1> student@<внутренний IP app-1>`.

**Ловушка с `$`.** При `--metadata-from-file` yc сам подставляет переменные окружения на место `$ИМЯ`. Например, `$uri` в конфиге nginx превратится в пустую строку, nginx начнёт отвечать 301, и цели станут `UNHEALTHY`. Поэтому в шаблоне нет ни одного `$ИМЯ`, а `create.sh` проверяет это перед созданием машин. `$(hostname)` yc не трогает.

## Уборка

`destroy.sh` удаляет ресурсы в обратном порядке: балансировщик → целевая группа → машины → диски → подсети (перед этим от подсети отвязывается таблица) → таблица маршрутизации → NAT-шлюз → сеть. В конце он сам показывает, что ресурсов с префиксом не осталось, и возвращает 0. Если ресурса уже нет, скрипт его просто не найдёт, поэтому его можно запускать на любом состоянии стенда.

## Файлы

| Файл | Что внутри |
|---|---|
| `create.sh` | поднимает стенд, повторный запуск безопасен |
| `check.sh` | 4 проверки, код возврата 0 или 1 |
| `destroy.sh` | удаляет всё с префиксом (или с меткой) |
| `cloud-init.tpl.yaml` | шаблон настройки машин; готовый `cloud-init.yaml` собирается при запуске и лежит в `.gitignore` |
| `расхождения.md` | чего скрипт не умеет — к сравнению с Terraform |
